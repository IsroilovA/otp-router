# Documentation

- Describe product requirements, business rules, external guarantees, and essential operator actions. Code, schemas, migrations, and executable examples own implementation details.
- Do not duplicate field/default/endpoint inventories, signatures, SQL layouts, algorithms, or source walkthroughs. Link to their owner or generated reference.
- Give each contract one home; link from other guides. Keep architectural conventions in scoped `AGENTS.md` files.
- Remove stale research, superseded advice, and repeated prose. Preserve unique requirements before deleting a document and update inbound links.
- Retain external protocol sources only where they explain a current constraint or operator decision. Distinguish required behavior from observed implementation; report conflicts rather than documenting bugs as requirements.
